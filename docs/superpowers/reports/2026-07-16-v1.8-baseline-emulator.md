# Afterbird v1.8 Baseline — fresh build on emulator

Date: 2026-07-16
Build: `chrome_public_apk` from clean Chromium 132.0.6834.83 checkout + afterbird
overlay, built on serv (80c/94G), APK 251 MB, `com.danosito.afterbird`
versionName=132.0.6834.83.
Device: local emulator `emulator-5554`, AVD `maximum_gapi35` (Android 15, API 35,
Google APIs, arm64).

This is the reference point before the M151 bump. Every prior diagnostic was
re-verified on a from-scratch build.

## Verified working

- **Build pipeline reproduces** end to end (fetch tag → gclient sync → overlay →
  gn gen → autoninja). Needed one fix: googlesource is throttled from RU, git
  fetch stalled <1000 B/s. Fixed by (a) routing through the on-box xray socks5
  (`127.0.0.1:10808`) for the tag fetch only, (b) disabling git's low-speed
  abort during pack (`ci/chromium_android_pipeline.sh`, `AFTERBIRD_GIT_LOW_SPEED_*`).
  gclient sync must NOT go through ALL_PROXY (breaks vpython venv SOCKS).
- **Browser launches**, FRE ("Use without an account") works, navigation works.
- **chrome://extensions loads** (Polymer renders: header, search, "+ (from store)",
  Developer mode toggle). Dev-mode toggle persists.
- **Main menu** has Extensions + Developer tools entries.

## Confirmed broken (matches prior diagnostics)

1. **DevTools — root cause verified verbatim.** First menu tap is a no-op
   (async port race — `EnsureServerStarted` returns port 0). Second tap opens a
   new tab to
   `chrome-devtools-frontend.appspot.com/serve_rev/@03d59cf5…/inspector.html?ws=127.0.0.1:34903/devtools/page/…`
   which renders blank. logcat:
   `[ERROR:devtools_http_handler.cc(778)] Rejected an incoming WebSocket
   connection from the https://chrome-devtools-frontend.appspot.com origin. Use
   the command line flag --remote-allow-origins=…`.
   → Exactly the M111 Origin-allowlist rejection predicted. Fix needs both
   `--remote-allow-origins` (or local frontend bundling) AND async port handoff.

2. **uBlock Origin did not load** via the `/data/local/tmp/afterbird-load-extension`
   fallback file (file is world-readable but the extensions list stayed empty;
   non-debuggable isolated_app likely can't read /data/local/tmp, or the fallback
   path isn't consumed on this build). adblock.turtlecute.org reported 21/133
   (16%) blocked — that's page static-filter noise, not uBO. Needs the CWS/load
   path re-verified once extensions actually install. **Loading mechanism itself
   is a baseline gap for the test harness** — can't rely on cmdline load.

3. **CWS shows "The Chrome Web Store is only available on desktop"** — Afterbird
   does not spoof a desktop UA the way Kiwi did (`PersonalizeResults.java`).
   Store install path can't even start from the mobile-gated page.

4. **`Unknown Extension API - developerPrivate.dismissSafetyHubExtensionsMenuNotification`**
   still logged on chrome://extensions open (harmless, but stub surface is
   incomplete).

5. **chrome:// URLs not launchable via `am` intents** (neither VIEW nor `-n … -d`).
   Only omnibox navigation works. Emulator smoke script's intent-based internal
   page checks are therefore invalid for this build.

## Implications for the plan

- The build path is solid and reproducible — good foundation.
- Every headline feature (uBO, DevTools, CWS install) is confirmed broken on 132
  exactly as the desk research predicted, which strengthens the case for the
  M151 upstream-path switch over patching 132.
- The test harness must own extension loading (not depend on cmdline) and must
  navigate via omnibox/CDP, not `am` intents.
