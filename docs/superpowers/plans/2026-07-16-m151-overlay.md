# M151 overlay plan — drop the custom layer, ride upstream

Target tag: **151.0.7922.38**. Strategy confirmed against the real synced M151
tree.

## Drop entirely (custom parallel reimplementation, superseded by upstream)

All 30 files under:
- `chrome/browser/extensions/desktop_android/**` — stock M151 has **no such
  directory**; the real extension code lives in `chrome/browser/extensions/`
  with `is_android` sections. Our stubs/install-coordinator/webstore shim/
  developer_private backend/extension_system are all replaced by upstream.
- `chrome/browser/extensions/android/**` — custom `app_menu_bridge`,
  `devtools_bridge` (the 403 one), install bridges, `ExtensionMenuManager`,
  `AppMenuBridge.java`. Replaced by upstream + Cromite-style phone-UI glue.

Also revisit for deletion once building: the 132-specific edits to
`chrome/common/extensions/api/api_sources.gni`, `extensions/**/BUILD.gn`
assertion relaxations, and the `desktop_android_stub_apis` schema plumbing.

## Keep / adapt (genuine deltas upstream lacks)

1. **Build args** — `.build/production_build_reference/args.gn`: set
   `enable_desktop_android_extensions = true` (now pulls the REAL stack). Add a
   **test variant** that is debuggable + exposes the `chrome_devtools_remote`
   CDP socket so the Playwright harness attaches (release build keeps it shut).
2. **Corp-gate un-gate** — `chrome/browser/extensions/extension_management.cc`
   `ExtensionsEnabledForDesktopAndroid()` (line ~184) currently requires
   `kEnableExtensionsForCorpDesktopAndroid` + corp account. Patch to return
   `true` unconditionally (or default the feature on).
3. **MV2 re-enable** — `extensions/browser/mv2_deprecation_impact_checker.cc`
   `IsExtensionAffected(int,Type,Location)`: add `return false;` at the top.
   Single choke point; neuters install-block / enable-block / auto-disable /
   management-policy for MV2. Lets uBO (bundled) run.
4. **Phone-UI adaptation** — upstream desktop-android extensions assume a
   desktop-ish UI. Port the minimal Cromite-style glue (GPL-2.0 — read as a map,
   do not copy) to surface: chrome://extensions reachability, the extensions
   entry in the app menu, and extension action popups on a phone form factor.
5. **DevTools menu entry** — wire the main-menu "Developer tools" item to
   upstream `chrome/browser/devtools/android/DevToolsWindowAndroid.openDevTools`
   instead of the deleted custom bridge. No appspot, no WebSocket 403.
6. **Branding** — package `com.danosito.afterbird`, app name, icons, the
   `google_api_key`/client-id block (or neutralize for the googleless build).
7. **CWS usability** — if the store still desktop-gates on phone UA, port the
   Kiwi/Cromite UA-spoof for `chromewebstore.google.com` so install can start.
   (Verify whether upstream one-click install already works before adding.)

## Sequence

1. Build **stock M151 + args flags only** (minimal overlay: args + package
   name) → install → measure how much works out of the box (Ultimatum/Cromite
   say: a lot). This sizes the remaining delta empirically.
2. Add gate patches (2, 3) → uBO + general extensions load.
3. Add phone-UI glue (4) + DevTools menu (5) as needed by test results.
4. Branding (6), CWS UA (7) as needed.
5. Harness `android` target against the CDP-enabled build; grow specs.
